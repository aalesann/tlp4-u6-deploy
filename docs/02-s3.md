# 02 - S3: almacenamiento de objetos

## Concepto

**S3** guarda *objetos* (archivos) dentro de *buckets*. No es un disco: no hay carpetas
reales, solo claves (`key`) como `fotos/gato.png`. Se accede por HTTP.

### ¿Por qué no guardar los archivos en el servidor Express?

- Si el servidor se reinicia o se reemplaza, los archivos desaparecen.
- Si hay dos instancias del servidor, cada una tiene archivos distintos.
- El disco del servidor es caro y limitado comparado con S3.

La regla: **el servidor es descartable, los datos viven en servicios aparte**.

### URL prefirmada

El bucket es privado. Para que el navegador descargue un archivo sin exponer
credenciales, el backend genera una **URL prefirmada**: un enlace temporal con la firma
incluida. En `backend/src/server.js` expira a los 300 segundos.

## Cómo lo usa la aplicación

`POST /files` hace tres cosas, en este orden:

1. Sube el archivo a S3 (`PutObjectCommand`) con una clave única (`uuid-nombre`).
2. Guarda los metadatos en PostgreSQL (ver guía 05).
3. Publica un evento en SQS (ver guía 04).

`GET /files` lee los metadatos y devuelve una URL prefirmada por archivo.

## Con la línea de comandos

```bash
echo "hola nube" > hola.txt
./scripts/aws.sh s3 cp hola.txt s3://tlp4-uploads/hola.txt
./scripts/aws.sh s3 ls s3://tlp4-uploads/
./scripts/aws.sh s3 cp s3://tlp4-uploads/hola.txt -
```

## Ejercicios

1. Sube un archivo desde React y búscalo con `./scripts/aws.sh s3 ls s3://tlp4-uploads/`.
   ¿Por qué el nombre tiene un UUID adelante?
2. Copia la URL de descarga desde la pestaña Red del navegador y mírala: ¿qué parámetros
   tiene? ¿Qué pasa si la abres pasados 5 minutos?
3. Intenta abrir `http://localhost:4566/tlp4-uploads/<clave>` sin firma. ¿Qué responde?
4. Cambia `expiresIn` a 10 segundos en `server.js`, reinicia y comprueba el vencimiento.
5. Agrega validación en `POST /files`: aceptar solo imágenes (`image/*`).
